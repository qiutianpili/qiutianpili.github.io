彻底关闭 Windows 的“基于虚拟化的安全性”（VBS）

只在 Windows 安全中心关掉开关并不能彻底关闭 VBS（Virtualization-based Security）：底层的虚拟机监控程序（Hyper-V Hypervisor）仍可能随系统引导启动。要彻底关闭，需要从系统设置、引导配置（BCD）、组策略/注册表三个层面一起处理，再关掉依赖它的可选功能。

想省事可以直接用微软官方脚本一键关闭，见 用微软官方工具关闭 VBS。本文是不借助脚本的手动做法。

第一步：关闭“内存完整性”（HVCI）

  1. 按 Win + S 搜索并打开 Windows 安全中心。
  2. 依次点击 设备安全性 → 内核隔离详细信息。
  3. 把 内存完整性（以及若有的“固件保护”）开关切换为 关。

第二步：从引导层关闭 Hypervisor（最关键）

这是阻止 VBS 启动最核心的一步。只要 Windows 在引导阶段加载了底层 Hypervisor，VBS 就可能保持待命或运行状态。

  1. 右键点击开始菜单，选择 终端（管理员） 或 命令提示符（管理员）。
  2. 输入以下命令并回车：
bcdedit /set hypervisorlaunchtype off

看到“操作成功完成”即可。该命令禁止系统在开机引导时加载 Windows 虚拟机监控程序。

第三步：配置组策略与注册表（防止被策略重新打开）

1. 组策略（专业版 / 企业版 / 教育版）

  1. 按 Win + R 输入 gpedit.msc 并回车。
  2. 导航至 计算机配置 → 管理模板 → 系统 → Device Guard（或“设备保护”）。
  3. 双击右侧的 打开基于虚拟化的安全性（Turn On Virtualization Based Security）。
  4. 将其改为 已禁用，点击确定。

2. 注册表（所有版本，包括家庭版）

  1. 按 Win + R 输入 regedit 打开注册表编辑器。
  2. 定位到下面的路径，把 EnableVirtualizationBasedSecurity 和 RequirePlatformSecurityFeatures 都改为 0（没有就新建 DWORD 32 位值）：
HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\DeviceGuard
  1. 再定位到下面的路径，把 Enabled 改为 0：
HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\DeviceGuard\Scenarios\HypervisorEnforcedCodeIntegrity

也可以在管理员终端里一次性写入，效果相同：

reg add "HKLM\SYSTEM\CurrentControlSet\Control\DeviceGuard" /v EnableVirtualizationBasedSecurity /t REG_DWORD /d 0 /f
reg add "HKLM\SYSTEM\CurrentControlSet\Control\DeviceGuard" /v RequirePlatformSecurityFeatures /t REG_DWORD /d 0 /f
reg add "HKLM\SYSTEM\CurrentControlSet\Control\DeviceGuard\Scenarios\HypervisorEnforcedCodeIntegrity" /v Enabled /t REG_DWORD /d 0 /f

第四步：关闭依赖 Hypervisor 的可选功能

装了强依赖 Hypervisor 的系统组件，也可能重新触发虚拟化安全机制。

  1. 按 Win + R 输入 optionalfeatures，打开“启用或关闭 Windows 功能”。
  2. 取消勾选以下组件（未安装则忽略）：
    • Hyper-V
    • 虚拟机平台（Virtual Machine Platform）
    • Windows 虚拟机监控程序平台（Windows Hypervisor Platform）
    • Windows 沙盒（Windows Sandbox）
  3. 点击确定，等待系统应用更改。

第五步：重启并验证

完成以上配置后重启电脑，进入系统后验证：

  1. 按 Win + R 输入 msinfo32 打开 系统信息。
  2. 在“系统摘要”右侧向下找到：
    • 基于虚拟化的安全性：应显示 未启用；
    • 基于虚拟化的安全性运行中的服务：应为 无 或空。

注意事项与恢复

  • 不要在 BIOS 里关 CPU 虚拟化（Intel VT-x / AMD-V、SVM）。这样虽能粗暴关掉 VBS，但 VMware Workstation、VirtualBox、安卓模拟器等也会完全无法运行。上面的 bcdedit 命令已经能在保留硬件虚拟化的同时剥离 VBS。
  • 对 WSL2 / WSA 的影响：hypervisorlaunchtype off 会让 WSL2 和 WSA 无法运行。
  • VBS 是一项安全防护，关闭会降低对内核级恶意软件的防御；公司电脑若由组策略 / Intune 管理，可能会被重新打开。

以后需要重新启用 VBS 或使用 WSL2，在管理员终端执行下面的命令后重启即可（第一、三、四步改过的开关按需改回）：

bcdedit /set hypervisorlaunchtype auto
