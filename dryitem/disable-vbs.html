用微软官方工具关闭基于虚拟化的安全性（VBS）

Windows 10/11 默认可能开着“基于虚拟化的安全性”（VBS），包括内存完整性（HVCI）和 Credential Guard。它会占用一部分性能，还会让 VMware、VirtualBox、部分游戏反作弊和驱动出问题。微软下载中心的 Device Guard and Credential Guard hardware readiness tool（DG_Readiness，v3.6）本来是检测和开启这些功能的脚本，但它也能一键彻底关闭 VBS，这正是它最常用的用途。

下载

从微软官方页面下载 dgreadiness_v3.6.zip（约 31.7 KB），解压到任意文件夹，例如 C:\dgreadiness_v3.6：

微软下载页面

关闭 VBS

以管理员身份打开 PowerShell，进入解压目录后依次运行：

cd C:\dgreadiness_v3.6
Set-ExecutionPolicy Bypass -Scope Process -Force
.\DG_Readiness_Tool_v3.6.ps1 -Disable -AutoReboot

第二行只对当前窗口临时放行脚本，关掉窗口就恢复。-AutoReboot 会让电脑自动重启。

重启时要手动确认

重启后会先出现一个蓝/黑底的英文提示，问你是否关闭 Credential Guard / VBS。按提示连续按 F3（有的机器是 Windows 键）确认，否则这次关闭不会生效。确认后系统正常启动。

检查是否已关闭

按 Win + R 输入 msinfo32，在“系统摘要”里看“基于虚拟化的安全性”，显示未启用即成功。也可以用 PowerShell：

(Get-CimInstance -Namespace root\Microsoft\Windows\DeviceGuard -ClassName Win32_DeviceGuard).VirtualizationBasedSecurityStatus

返回 0 表示已关闭。

它做了什么

  • 删除 HKLM\SYSTEM\CurrentControlSet\Control\DeviceGuard 下开启 VBS、内存完整性的注册表项，以及 Lsa 下的 LsaCfgFlags（Credential Guard）。
  • 关闭 Hyper-V 虚拟机监控程序功能。
  • 用 SecConfig.efi 在下次启动时清除 UEFI 里锁定的 VBS 设置，所以重启时需要按键确认。

注意事项

  • 关闭后 Hyper-V、WSL2、Windows 沙盒、Docker Desktop（WSL2 后端）等依赖虚拟化的功能也会停用，需要时再开回来。
  • 想恢复：运行 .\DG_Readiness_Tool_v3.6.ps1 -Enable -AutoReboot，或在“Windows 安全中心 → 设备安全性 → 内核隔离”里重新打开内存完整性。
  • VBS 是一项安全防护，关闭会降低对内核级恶意软件的防御，请按需使用。公司电脑若由组策略/Intune 管理，可能会被重新打开。
  • 官方说明支持 Windows 10（1607 起）和 Windows Server 2016，在 Windows 11 上同样常用。
